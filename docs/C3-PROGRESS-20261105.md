## Avance productivo acotado

1. **Revisión efímera y de un solo uso.** MessageEditor conserva canal, destinatario
   efectivo, texto, contacto y replyKey revisados en memoria. Consume la revisión
   ANTES de llamar a Android/onLaunch. Editar, cambiar homónimo/mecanismo, Volver o
   restaurar exige revisar de nuevo. Un callback viejo de Compose no puede lanzar
   dos veces ni usar texto posterior a la revisión. Se conserva el mecanismo de
   NativeLaunchSession para Intents y Replies.send para respuestas; no otro bus.
2. **Número inequívoco.** Se rechazan letras, códigos especiales, varios signos+
   y dígitos noASCII antes de normalizar; no se descartan silenciosamente para
   fabricar otro número. Se conserva el normalizador/country actual para números
   nacionales válidos. La revisión WhatsApp muestra el E164 exacto y lo vuelve a
   comprobar antes de preparar el enlace. Personal/Business fijan su paquete y
   texto exactos. No se asegura que el número tenga una cuenta de WhatsApp.
3. **Respuesta vigente.** Replies.send compara además los resultKey y la capacidad
   free-form de los RemoteInput revisados, incluso si el PendingIntent es el mismo.
   Consume localmente la entrada antes de solicitar el efecto; acción cancelada
   no vuelve a crear la entrada ni reintenta. Conserva paquete/conversación/grupo,
   conexión y presencia actuales. No garantiza exactly-once global si WhatsApp
   publica otra notificación ni confirma entrega en el destinatario.

No hay diseño nuevo: se conservan formulario compacto, controles, Focus B,
Geist/Obsidian, búsqueda/ranking, footer, permisos y contratos del overlay.
Se reutilizan canales personal/Business existentes. No nuevo selector de app,
lectura de chats, adjuntos RemoteInput, envío oculto, servicio ni transporte.
